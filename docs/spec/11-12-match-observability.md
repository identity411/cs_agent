## 0. 文档目的

回答三个问题：

1. **这个 agent 有没有在打？**（参战 / 开火 / 打子弹）
2. **打得怎么样？**（命中率、伤害、K/D）
3. **有没有在该出现的位置出现？**（卡死率 = 没出 A/B 点；回防率 = 炸弹下在 A 时，人在 B 是否往 A 走）

同时给出一套可重复的口径，后续每次提交（新 `bundle_sha256`）都能按同一张表回填，避免只看比分把“队友带赢 / 对手不进攻”误判成 agent 变强。

本文只使用公共回放与公开 API；不声称拥有私有决策轨迹。指标反映**可观测行为**，不等于引擎内部的完整决策。

## 3. 指标定义

### 3.1 基本单位

- **seat-match**：一个账号的一个席位在一场对局中的观测。
- **live round**：有 `round_start` / `round_end`，且冻结时间结束后至少取到 1 帧的回合。
- **combat round**：该回合 seat 满足任一条件：`fire`（自己开火）、`hit`（自己命中）、被命中（`hit.target=seat`）、`kill`（击杀参与）、`death`（自己死亡）。
- **冻结结束**：`round_start.buy_freeze_end_tick`（本批为回合开始后 6 s）。
- **位置**：指标只使用 XY；Z 未参与卡死/回防判定。

### 3.2 参战 / 开火 / 子弹

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| `shots` | `fire` 事件中 `player=seat` 的数量（子弹数） | 参考，不是越高越好 |
| `shots_per_round` | `shots / live_rounds` | 参考 |
| `rounds_with_fire` | 至少 1 发 `fire` 的回合数 | 越高越好 |
| `fire_participation_rate` | `rounds_with_fire / live_rounds` | 越高越好 |
| `rounds_with_combat` | 至少 1 个 combat 事件的回合数 | 越高越好 |
| `combat_participation_rate` | `rounds_with_combat / live_rounds` | 越高越好 |
| `zero_shot_rate` | 0 发 `fire` 的回合占比 | 越低越好 |
| `lobby_fires` | 本场所有玩家的 `fire` 总数 | 数据质量上下文 |
| `agent_fire_share` | `seat shots / lobby_fires` | 参考 |
| `match_combat_participation` | 整场 seat 是否至少 1 个 combat 事件 | 是/否 |

**“参与对战”拆成两层**：整场是否进入过交火（`match_combat_participation`），以及按回合的交火参与率。另记录下包/拆包等 objective 动作，避免把“0 开火但下包”误判为完全没参与。

### 3.3 命中

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| `hits` | `hit` 事件中 `player=seat` 的数量 | 越高越好 |
| `accuracy_percent` | `hits / shots × 100`；0 发时为 N/A | 越高越好 |
| `damage` | `hit.amount` 求和 | 越高越好 |
| `kills` / `deaths` | 击杀参与 / 自己死亡 | 参考 |
| `per_round_accuracy_median` | 只对有开火的回合算 `hits/shots`，取中位数 | 越高越好 |

命中率受交战距离、目标是否移动、对手水平影响；**不能只看总体命中率**，需同时看每回合分布和异常回合（例如单回合数十发低命中）。

### 3.4 卡死 / 到点

**A/B 点区域**：任一 site 中心 XY 距离 ≤ `site.radius + 6.0`。本批地图半径：nevaio / borgo 4.0，dust2 6.1–6.3。

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| `reached_site` | 冻结结束后到回合结束，任一采样点进入 A 或 B 区域 | 是/否 |
| `site_reach_rate` | 到点回合 / live rounds | 越高越好 |
| `no_site_rate`（用户口径卡死率） | 整回合从未进入 A/B 区域 | 越低越好 |
| `true_stuck_rate` | 未到点 **且** 离己方出生点中心最远 < 20 units | 越低越好 |
| `no_site_moving_rate` | 未到点但离开出生点 ≥ 20 units（走了/在别处交火，但不是“原地卡死”） | 越低越好，需结合交火看 |
| `spawn_stuck_rate` | 离出生点最远 ≤ 12 units（基本没出出生点） | 越低越好 |
| `time_to_site_s` | 首次进入 A/B 区域 - 冻结结束（秒） | 越低越好 |
| `reached_within_40s` | 40 s 内到点 | 越高越好 |

**为什么拆 `no_site` 和 `true_stuck`**：v0.01 有回合在出生点不动（真卡死），也有回合在别处交火/转点但没到 A/B（未到点但不是卡死）。只报“未到点率”会把两者混在一起；只报“真卡死”又会漏掉“该到点却没到”的目标问题。两列都记录。

### 3.5 回防 / 转点

对每个 `plant_complete` 回合：

1. 取 `plant_complete_detail.position` 作为炸弹位置；没有 detail 时退回 site 中心。
2. 取下包后第一个采样帧；`alive=false` 则不算回防机会（仍记录下包）。
3. `initial_dist` = 该帧到炸弹的 XY 距离。
4. **回防机会**：`alive_at_plant` 且 `initial_dist > 25 units`。
5. **回防启动**：之后存活期间到炸弹距离下降 ≥ 10 units，或 seat 自己 `defuse_start`。
6. **回防到位**：存活期间最小距离 ≤ 8 units，或 seat 自己 `defuse_start`。

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| `rotation_opportunities` | 满足机会的回合数 | 分母 |
| `rotation_attempt_rate` | 启动回合 / 机会回合 | 越高越好 |
| `rotation_arrival_rate` | 到位回合 / 机会回合 | 越高越好 |
| `closing_distance` | `initial_dist - min_dist` | 越高越好 |
| `required_speed` | `(initial_dist - 8) / 可用秒数` | 参考；>5.5 u/s 可标“物理上很紧” |

用户例子“A 点下包、人在 B 活着但没往 A/B 走”对应的就是 `opportunity=true` 但 `attempt=false`；如果走了但没赶到，则是 `attempt=true, arrive=false`。

> 口径说明：用户原话中“没往 B 走”按“没往炸弹点（本例 A）走”理解。本文同时统计 T 侧下包后的回炸弹位（post-plant 防守/转点）和 CT 侧真正的 retake；表中的“侧”列区分二者。若只想看 CT retake，按 `side=defend` 筛选。

### 3.6 数据质量门禁

| 标记 | 条件 | 处理 |
| --- | --- | --- |
| `lobby_zero_combat` | 全场所有玩家 `fire` 总数 = 0 | 不用于交火/命中/回防结论；移动/卡死可用但注明无交火压力 |
| `fault_present` | 出现 `fault` 事件 | 记录数量和 seat；若影响本场行为，标注 |
| `outlier_burst` | 单回合 shots 远高于中位数且命中率异常低 | 在命中率结论中单列，不直接删除 |
| `small_sample` | 版本 <2 场正常交火对局或 <40 live rounds | 结论标“暂定” |
| 不同地图/席位 | 对比双方不是同图同 seat | 需要 per-map / per-side 拆分，不能只看合并值 |

## 4. 变好 / 变坏判定规则

### 4.1 方向与阈值

| 指标 | 方向 | “变好”门槛 | “变坏”门槛 |
| --- | --- | --- | --- |
| 参战率 / 开火率 / 交火率 | 越高越好 | +10 pp | −10 pp |
| 卡死率 / 未到点率 / 出生点滞留率 | 越低越好 | −10 pp | +10 pp |
| 命中率 | 越高越好 | +5 pp | −5 pp |
| 回防启动率 / 到位率 | 越高越好 | +10 pp | −10 pp |
| 每回合子弹数 | 参考 | +20% | −20% |
| 到点时间中位数 | 越低越好 | −20% 或 −10 s | +20% 或 +10 s |

pp = 百分点。命中率、回合率都按**回合/子弹**聚合，不用“场均值”再做平均。

### 4.2 判定顺序

1. **先看数据质量**：`lobby_zero_combat` 的场次从交火/命中/回防对比中剔除；移动/卡死保留但标注。
2. **再看每场**：同一版本每场单独列表；不能只报合并值。
3. **再看合并**：按 live rounds 合并；如果每场方向不一致，判“不确定”。
4. **样本门槛**：每版本至少 2 场正常交火对局、≥40 live rounds 才能写“确认”；否则写“暂定/方向性”。
5. **结果与行为分开**：比分、回合胜率只作为结果指标；不能用“赢了”替代参战/命中/卡死结论。

### 4.3 输出标签

- `变好（确认 / 方向性 / 暂定）`
- `变坏（确认 / 方向性 / 暂定）`
- `无显著变化`（未超过阈值）
- `证据不足`（样本/数据质量不够）
- `数据异常`（0 交火 lobby、fault 等）

## 9. 已知限制

1. **公开投影**：`public_events` 只包含公开可见事件；没有私有观测/决策轨迹。命中/开火可以证明，但“为什么没开枪”不能从公开回放完全证明。
2. **2 s 采样**：可能漏掉短暂进入 A/B 区域或短距离回防；对卡死/到点率影响小，对“是否曾经贴近炸弹”可能有边界误差。
3. **到点口径是策略相关**：baseline 的目标是站点中心；真实比赛中防守方可能故意站在站点外架枪，这种“未到点”不等于失误。本文对 baseline 使用该口径，但不把它当成通用强弱指标。
4. **回防到位阈值 8 units** 比实际拆包触发半径（2 units）宽松；0/10 的到位率说明即使按宽松口径也没到。但 T 侧不必站到炸弹上，12.9 units 可能已是合理防守位；该指标对 CT retake 更有解释力。
5. **地图/席位/对手不同**：v0.01 的对手可能被卡住/站桩，命中率会偏高；v0.02-account2 的对手会移动。不能把命中率差异全部归因于代码。
6. **样本小**：确认门槛是每版本 ≥2 场正常交火对局、≥40 live rounds；当前 v0.02 只有 1 场正常交火局，所有对比标“暂定”。
7. **全场 0 交火 lobby 的成因**：公开帧显示对手队 seats 5–9 在 T/CT 两侧均不购买、不移动、`speed=0`/idle；我方 seats 1/2/3 购买并移动，seat 0 fault、seat 4 idle。可排除“我方全队冻结/全局地图冻结”，但平台侧原因（对手进程/席位状态）仍需平台日志确认；本场不能用于交火/命中结论。
8. **fault 事件语义**：当前只按公开事件计数，不知道 fault 是否等于崩溃/重连/被判负。
